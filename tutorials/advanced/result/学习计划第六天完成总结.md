## 2. WAL 核心概念与来源说明

### 2.1 核心概念

#### 2.1.1 概念要点（来源均为业界权威资料）

- WAL 是确保持久性与崩溃一致性的通用机制：所有对数据的修改必须先追加到日志（顺序写），再更新内存结构；崩溃后通过日志重放恢复未持久化的数据。
- 核心思想：先写日志，再写数据；日志采用追加式顺序写，恢复按顺序回放。

#### 2.1.2 参考资料（可直接检索验证）

- Gray, Reuter. Transaction Processing: Concepts and Techniques. Morgan Kaufmann, 1992.
- PostgreSQL Documentation: [Write-Ahead Logging (WAL)](https://www.postgresql.org/docs/current/wal-intro.html)
- SQLite Documentation: [Write-Ahead Logging](https://sqlite.org/wal.html)

## 3. 项目实现要点（源码位置与行为）

### 3.1 实现细节

#### 3.1.1 日志格式

- 文本行格式：`operation|key|value|timestamp`（`WriteAheadLog.java:162-164`）。
- 解析逻辑：`fromString` 支持 `PUT` / `DELETE`，`value` 为空表示删除墓碑（`WriteAheadLog.java:166-181`）。

#### 3.1.2 写入路径（先写 WAL，再写 MemTable）

- `LSMTree.put`：先 `wal.append(WriteAheadLog.LogEntry.put(key, value))`，再写入活跃 `MemTable`，必要时触发刷盘（`src/main/java/com/brianxiadong/lsmtree/LSMTree.java:102-111`）。
- `LSMTree.delete`：先 `wal.append(WriteAheadLog.LogEntry.delete(key))`，再在 `MemTable` 标记删除（`src/main/java/com/brianxiadong/lsmtree/LSMTree.java:135-144`）。

#### 3.1.3 恢复流程（SSTable + WAL 双阶段）

- 第一步：加载现有 `SSTable` 列表（`LSMTree.java:470-482`）。
- 第二步：`wal.recover()` 逐行解析日志，并将未刷盘的 `PUT` / `DELETE` 回放到活跃 `MemTable`（`LSMTree.java:484-493`，`WriteAheadLog.java:89-103`）。

#### 3.1.4 同步策略（持久化时机）

- 追加写入采用 `AsynchronousFileChannel`；达到批量阈值或时间阈值时执行 `fsync`（`WriteAheadLog.java:39-66`）。
- 阈值配置来源：`lsm.wal.sync.batch`（默认 64），`lsm.wal.sync.interval.ms`（默认 50 ms），由构造器读取（`LSMTree.java:55-56`）。
- `fsync` 由异步 I/O 管理器统一触发（`NioAsyncIOManager.syncAsync`，`src/main/java/com/brianxiadong/lsmtree/NioAsyncIOManager.java:126-144`）。

#### 3.1.5 检查点（Checkpoint）与日志截断

- 刷盘 `MemTable` 成为 `SSTable` 后调用 `wal.checkpoint()`：关闭通道、等待未完成写、`fsync`、删除旧日志并重新打开新日志文件（`WriteAheadLog.java:68-87`）。
- 触发点：`flushImmutableMemTable` 在成功创建 `SSTable` 后进行检查点（`LSMTree.java:356-366`）。

#### 3.1.6 监控指标

- 暴露 `lsm.wal.size.bytes` 指标用于监控 WAL 文件大小（`LSMTree.java:68-69`）。

### 4.1 代码示例

#### 4.1.1 写入与删除示例（演示 WAL 生效）

```java
// 示例：写入与删除操作，先写 WAL，再更新内存
// 目的：验证 WAL 追加与 MemTable 更新的顺序一致性
LSMTree tree = new LSMTree("data", 1024);
tree.put("user:1", "Alice");   // 追加 WAL: PUT|user:1|Alice|ts
tree.delete("user:1");           // 追加 WAL: DELETE|user:1||ts
tree.close();                     // 关闭前会 flush 并关闭 WAL
```

## 5. 性能分析与优化建议（含依据）

### 5.1 性能分析

#### 5.1.1 异步 I/O 与批量 `fsync`

- 依据：`WriteAheadLog.append` 在达到批量或间隔阈值时统一 `fsync`（`WriteAheadLog.java:49-66`）。
- 建议：根据写入负载调整 `lsm.wal.sync.batch` 与 `lsm.wal.sync.interval.ms`，在吞吐与持久性之间平衡。

#### 5.1.2 日志轮转（建议实现）

- 需求：避免 WAL 文件无限增长，缩短恢复时间。
- 建议规则：按大小（如 128 MB）或时间（如 10 分钟）轮转，并维护最小必要段用于恢复。

#### 5.1.3 校验与二进制格式（可选）

- 引入条目级校验和，降低损坏风险；采用二进制编码减少解析开销与磁盘占用。
- 取舍：文本易调试，二进制更高效；可按运行模式切换。

#### 5.1.4 检查点触发优化

- 依据：当前在 `SSTable` 写入成功后触发检查点（`LSMTree.java:356-366`）。
- 建议：结合写入速率与恢复时间目标，动态调整刷盘与检查点策略，避免过度频繁截断影响持久性窗口。
