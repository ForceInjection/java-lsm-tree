## 2. 压缩策略核心概念与来源说明

### 2.1 核心概念

#### 2.1.1 概念要点（来源均为业界权威资料）

- **压缩（Compaction）**：LSM Tree 的核心维护操作，将多个小 SSTable 文件合并为更大的文件，同时删除过期数据和重复键
- **Leveled Compaction**：将数据组织成多个层级，每个层级有固定的大小限制，压缩时从高层级向低层级合并
- **压缩触发条件**：基于文件数量、层级大小、写入放大等指标决定何时启动压缩

#### 2.1.2 参考资料（可直接检索验证）

- O'Neil, Cheng, Gawlick, O'Neil. "The Log-Structured Merge-Tree (LSM-Tree)". Acta Informatica, 1996.
- Apache Cassandra Documentation: [Compaction Strategies](https://cassandra.apache.org/doc/latest/cassandra/operating/compaction/)
- RocksDB Documentation: [Compaction](https://github.com/facebook/rocksdb/wiki/Compaction)

- 接口定义：`CompactionStrategy.java` 定义了压缩策略的核心接口（`CompactionStrategy.java:1-25`）
- 核心方法：`needsCompaction()` 判断是否需要压缩，`compact()` 执行压缩操作，`selectCompactionTask()` 选择压缩任务

#### 3.1.2 Leveled Compaction 实现

- 层级分组：`groupByLevel()` 方法按层级对 SSTable 文件进行分组（`LeveledCompactionStrategy.java:45-60`）
- 压缩触发：基于每个层级的文件数量阈值判断是否需要压缩（`LeveledCompactionStrategy.java:20-40`）
- 层级大小计算：第 0 层有特殊大小限制，其他层级按指数增长（`LeveledCompactionStrategy.java:35-38`）

#### 3.1.3 压缩执行流程

- 文件选择：选择需要压缩的层级和文件
- 合并去重：读取多个 SSTable 文件，合并键值对并去除重复键
- 写入新文件：生成新的压缩后的 SSTable 文件
- 清理旧文件：删除已被合并的旧 SSTable 文件

#### 3.1.4 配置参数

- `maxLevelSize`：每个层级的最大文件数量限制（`LeveledCompactionStrategy.java:15`）
- `levelSizeMultiplier`：层级大小乘数，控制层级容量的增长（`LeveledCompactionStrategy.java:16`）

## 5. 性能分析与优化建议

### 5.1 性能影响分析

#### 5.1.1 写入放大（Write Amplification）

- **问题**：压缩过程中数据被多次重写，导致写入放大
- **影响**：增加磁盘 I/O，降低写入吞吐量
- **优化**：调整压缩频率和策略参数，平衡写入放大和读取性能

#### 5.1.2 压缩开销

- **CPU 开销**：合并排序和去重操作消耗 CPU 资源
- **磁盘 I/O**：读取多个输入文件，写入输出文件
- **内存使用**：需要缓冲区来处理文件合并

### 5.2 优化建议

#### 5.2.1 参数调优

- **调整层级大小**：根据工作负载特征优化 `maxLevelSize` 和 `levelSizeMultiplier`
- **动态压缩触发**：基于系统负载动态调整压缩阈值
- **压缩优先级**：优先压缩读取频繁的层级

#### 5.2.2 算法优化

- **增量压缩**：只压缩发生变化的部分，减少全量压缩的开销
- **并行压缩**：利用多线程并行处理不同层级的压缩任务
- **压缩调度**：智能调度压缩任务，避免在高峰期执行
